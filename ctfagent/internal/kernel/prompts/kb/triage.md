# 限时多题：分诊（triage）与时间预算

赛制给的是**总时长**（例如几小时打完一整套题），不是每题均分。
所以解题速度的一半来自"先做哪道、什么时候放弃、什么东西能复用"。

## 一、开局 5 分钟：把"零成本得分点"全摘掉

对每一道拿到手的题，先用**一轮并发**把下面这些一次性打完（不要一项一轮）：

1. `ports(host)` —— 旁路端口常常就是主线（没有网关管的后端服务）
2. `recon(url)` —— 指纹 + 目录 + 敏感文件
3. `GET /` 的**完整响应头**：`Server` / `X-Powered-By` / `Set-Cookie` / `Content-Encoding`
4. 首页与 `/assets/js/*.js`：**硬编码 API Key、内部地址、参数名、测试账号**
5. 自述接口：`/api/docs`、`/openapi.json`、`/api/status`、`/api/config`、`/version`
6. 默认凭据：组件默认口令（`admin/admin`、`geoserver/geoserver`、`minioadmin/minioadmin` …）

> 这一步经常直接结束一道题：有的答案就在响应头/cookie 里，有的账号就写在登录页。

## 二、每类题的"低垂果实阶梯"（从便宜到贵）

| 类别 | 顺序 |
|---|---|
| Web 应用 | 响应头/JS → 测试账号 → 源码/备份 → 文件读写点（下载/预览/导入/导出/日志） → 注入 → 反序列化 |
| 已知组件 | 版本指纹 → 未授权接口 → 默认口令 → 已知 CVE 的**最小验证**（不要整条链一次写完） |
| 云 / 托管 | 自述接口 → 公开对象/文档 → 未授权配置接口 → SSRF 打元数据 → 凭据范围 → 制品（tfstate/.env） |
| 面板 / 控制台 | 门禁（安全入口+验证码）→ 登录 → **文件读写接口**（不必 getshell） |
| 二进制逆向 | 跑一遍看输出 → `strings`/`objdump` → 找"数据落地"的常量 → 工具枚举变换 |
| 行协议服务 | 跑一遍所有动词 + 边界值 → 长度回显 → 越界读/未初始化 → 越界写 |
| 检测规避 | 先交干净基线 → 单变量枚举 → 组合 |

## 三、时间盒与止损（三条硬线）

1. **单点 15 分钟无新信息 → 换路线**（不是换措辞）。
2. **同一路线连续 3 次失败 → 记 `fact` 说明"为什么不行"，再开新分支**；别在同一个参数上重试第四次。
3. **已排除的路线写进态势**（"登录口无 SQLi/SSTI，盲注 7ms"），避免自己或后续轮次重复。

判"这题做不出来"之前必须五条都做过（见 `solver.md` §二点七）。

## 四、复用：同一批题里最值钱的东西

- **指纹复用**：同一套环境的组件/版本/默认口令高度重合。前一道题验证过的默认口令、接口形态，
  下一道先试一遍。
- **通道复用**：一条 SSRF / 一个上传点 / 一个命令执行点，往往能同时打多台内网机器；
  把"能读能写能转发"的入口记成资产，别用完就丢。
- **payload 复用**：同一类漏洞的 payload 模板（反序列化、模板注入、WAF 绕过）写成一条命令，
  下次直接改参数，别重新推导。
- **凭据复用**：一套环境里各角色常共用一批口令；拿到一个口令先横向到所有已发现登录口。

## 五、提交纪律（血亏过的地方）

- **拿到答案立刻提交**，不要"再确认一下"、"再看看有没有更完整的"；
- **提交前后都不要重启/关闭容器**：很多平台的答案与实例绑定，换实例后旧答案作废；
- 无回执 ≠ 判错：先原样重放一次，确认前后缀/换行/大小写；
- 同一份数据在多处出现（数据库、缓存、页面）时，**只提交一次**，别换个地方再提交一遍。

## 六、答案落点清单（拿不到就想"是不是我找错地方了"）

排障顺序：先确认**这条链路真的执行了**，再按下面清单逐条对照，别默认"答案一定在某个文件里"。

| 落点 | 典型形态 |
|---|---|
| 命令 stdout / 响应体 | 直接回显、`debug.output` 这类调试字段 |
| **响应头 / Set-Cookie / 重定向** | 有的题答案就写在头或 cookie 里，`curl -i` 一秒解决 |
| 页面元素 / flash 消息 | 公告、`secret-box`、购买成功提示、一次性提示 |
| **异常 / 错误消息** | 500 页、`errors[0]`、堆栈文本里带命令输出 |
| 数据库字段 | 配置表（`config`/`oa_config`）、`system_*` 键、业务表 |
| 缓存 / 会话存储 | Redis `GET <key>`、session 文件 |
| 环境变量 / 启动参数 | `/proc/self/environ`、容器 env、启动脚本注入 |
| 文件系统 | 目标目录、备份目录、上传目录、解压出的 `*.tfstate` / `*.db` |
| 云凭据字段 | `SecretAccessKey`、token payload、STS/SAS 的 scope 内对象 |
| 内网服务的独立 socket | 本机 unix socket / 元数据 agent（不在文件系统里） |

**判据**：目标机器上"`find / -iname '*flag*'` 一无所获"不等于没有答案 ——
先去 `cat /entrypoint.sh`、`/start.sh`、`/hint.txt` 看它把答案交给谁（文件、DB、socket、环境变量）。

## 七、一轮里要"榨干"

- 互不依赖的调用**同一轮发完**（端口 + 目录 + 首页 + JS）；
- 能用专用工具一把梭的（`recon`/`ports`/`paramfuzz`/`fuzz`）不要写十条 `curl`；
- 探测类命令一律设短超时，别让一个挂死的点拖掉整轮。
