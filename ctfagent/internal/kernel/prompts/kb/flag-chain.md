# 多阶段目标链：推进清单

一条链通常有 3~5 个节点，每层各放一份目标数据（有时还有一份"诱饵"放在入口）。按下面顺序推进，
**每一步都要留下可复现的记录（地址、凭据、隧道方式、结果）**，避免来回重复探测。

## 一、先给整条链画地图

1. 入口页面/资源里找**迁移提示、注释、备份目录、调试工具**（很多入口直接给出下一跳）；
2. 拿到第一个执行能力（文件读 / 命令执行 / 上传）后，立刻做本机侦察：
   `id`、网段、`/etc/hosts`、启动脚本、历史命令、`ls /`；
3. 用**入口已有的通道**做端口探测（不要等出网）：能跑命令就用 `/dev/tcp`、
   能 SSRF 就 `http` 代理、能跑脚本就用 socket 并发；
4. 只对"活着的、像目标的"机器做全端口；宿主机网关（网段里的 `.1`）多数是平台侧，不是目标。

## 二、每台新机器上的固定动作

| 顺序 | 动作 | 目的 |
|---|---|---|
| 1 | `id; hostname -I` | 当前身份、第几个网段 |
| 2 | 看该层的目标文件（常见集中在一两个顶层目录） | 直接收这一层的答案 |
| 3 | 启动脚本 / 历史命令 / 配置 | 下一跳地址、凭据、权限设置 |
| 4 | `find / -perm -4000` | 提权捷径（解释器 SUID 最常见） |
| 5 | 数据库 / 缓存服务 | 另一份数据（常与页面上的同值，不要重复找） |

## 三、横向的三种通道，按可用性排

1. **已有 Web 执行点当隧道**（webshell 里跑语言自带 socket / `bash /dev/tcp`）——最稳，不依赖出网；
2. **应用自带的代理/转发/扫描动作**（备份目录里的工具页）——能转发 POST，等于交互式浏览器；
3. **借一台带客户端的机器当跳板**（`ssh`/`curl` 只在某些角色上存在，用它去打第三台）。

## 四、凭据与口令

- 先横向复用**入口拿到的口令**，再考虑爆破；
- 目标系统的**主题字典**（产品名/厂商名 + 年份/数字）命中率远高于通用表；
- 用户名取自泄露清单（通讯录、用户表、备份文件）；
- 压缩包口令通常是**最简单的数字串**，与 SSH 口令不同；
- 有速率限制时：单源、串行、间隔 ≥1s，命中即停；被封先等 10~15 分钟。

## 五、提交前

- **目标数据的编号不等于发现顺序**：同一台机器上的两份数据可能对应不同的编号；
- 先按"位置"整理（哪台机器、哪个文件、哪个接口），再逐个提交；
- 无回执不要当成错误：先重放同一份数据，确认格式（前后缀、换行、大小写）。
