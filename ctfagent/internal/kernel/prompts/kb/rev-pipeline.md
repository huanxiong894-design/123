# 二进制取数：解码后的字符串从不打印怎么办

一类题的通病：程序**把凭据解密到栈/堆缓冲区里，然后只打印 "accepted / denied"**。
`strings` 里看不到东西，运行时也看不到东西。这时目标不是"再找一个漏洞"，
而是**把那条数据流接出来**。按下面的顺序试，代价从低到高。

> **先做一条零成本判断**：如果那个"解码器"跑完一轮，**输出里一个来自 .data 的字节都没有**
> （只打印固定占位符），它大概率是**诱饵**。别硬摁着它逆，直接跳到 §8，
> 用 `unmix` 把 .data 那块定长高熵常量按字节还原 —— 这通常比继续逆解释器快一个数量级。

## 0. 先判定"数据流存在但不落地"

三个信号同时出现基本就能确定：

1. 二进制里有 `.data/.rodata` 的高熵常量块（32~64 字节，长度像 38/40/48）；
2. 主流程只 `puts("accepted")`，成功分支里有一段"逐字节异或/查表"的循环；
3. 解码循环写到 `[rsp+off]` 或某个 `mmap` 出来的页，之后**没有任何写入 stdout 的调用**。

反汇编里认这几类收尾：`lea rcx,[rsp+0xNN]` + 长度常量做循环 XOR、
`mov BYTE PTR [rsp+0xNN],0x0` 手动补 NUL —— 那就是"结果缓冲区"。

## 1. 首选：纯静态复现（最干净、可反复跑）

把循环按字节抄成 Python：读表、读常量、按同样顺序 XOR/加/移位。
**注意编译器魔法数**，它们常把循环变量取模写成乘法移位：

| 常量 | 含义 |
| --- | --- |
| `0xaaaaaaab >> 34` | `/ 6`（不是 `/ 3`！`>>33` 才是 `/ 3`） |
| `0x4ec4ec4f >> 35` | `/ 26` |
| `0xcccccccd >> 34` | `/ 10` |
| `imul eax, 0x1000193` + `xor` | FNV-1a 32 位（basis `0x811c9dc5`） |
| `0xc6ef3720` / `0x61c88647` | TEA/XTEA 轮常量 |
| `0x1505` + `h=h*33^c` | djb2 |

复现完要做**两条自检**：随机输入跑一遍本地二进制，比对其输出/返回值；
再用一个"已知全部字节"的输入验证你的模拟和真实缓冲区逐字节相等。

## 2. 次选：进程内取数（ptrace 断点）

不能纯静态（依赖库调用、依赖前序校验状态）时，直接断在"数据已就绪"的位置：

- 断点位置：解密循环的下一条指令（`cmp` 之后）、或密钥校验函数 `call` 的**下一条指令**；
- **EXEC（非 PIE）**：断点地址就是 objdump 里的 vaddr；
- **PIE**：运行时地址 = 基址 + vaddr，基址从 `/proc/<pid>/maps` 里按可执行文件路径取第一段起点；
- 到了断点直接读 `/proc/<pid>/mem`：
  - 栈缓冲区：`rsp + 偏移`（偏移来自 `lea rcx,[rsp+0xNN]`）；
  - **Go 二进制返回字符串**：返回值就在 `rax`(ptr)、`rbx`(len)，按 len 读内存即可。

配合"补丁绕过前置校验"最省事：把 `test eax,eax` 后面的 `jne` 改成 `jmp`（`75 xx`→`eb xx`），
就能用任意口令走到解密分支，再 dump。补丁只用于**本地观察**，不改服务端。

## 3. 再次：unicorn 模拟单个函数

只要函数是自包含的（只读 `.rodata/.data`、只写栈），模拟比逆向快得多：

```
UC_ARCH_X86/UC_MODE_64；按 PT_LOAD 段 mem_map + mem_write
栈自己 map 一块，rsp 指向中间；PIE 直接按 vaddr 跑（不必重定位）
fs_base 指向一小块伪造 TLS 并写入 fs:0x28 的 canary（否则栈保护分支跳飞）
hook_code 里遇到 ret 指令地址就 emu_stop，然后读 [entry_rsp - 帧大小 + 偏移]
```

坑：函数序言 `push` 会推进 rsp，**内部 rsp = 入口 rsp - (push 数*8 + sub 立即数)**，
读缓冲区时用内部 rsp 算，别用入口值。

## 4. Go 静态二进制的符号恢复

`-ldflags "-s -w"` 只删 symtab/DWARF，**pclntab 还在**：

- 搜索 magic `f1 ff ff ff`，其后是 `pad,pad,minLC,ptrSize,nfunc,nfiles,textStart,funcnameOff,...,pclnOff`；
- `functab` 在 `pclnOff` 处，每项 `{entryoff uint32, funcoff uint32}`，
  函数名在 `funcnameOff + nameOff`，地址 = `textStart + entryoff`；
- 拿到 `main.*` 地址后按上面第 2 条断点即可。

## 5. 自解密/自解包壳

"Packed / Self-Decrypt" 这类壳的通用拆法：

1. 口令来自 `.rodata` 的一张表逐字节 XOR 常数 —— 直接算出来（`pw[i] = tbl[i] ^ k`）；
2. 用口令派生 keystream（常见 djb2 → 每 4 字节取一次哈希的低字节，再 `h = h*33 ^ i`）；
3. `ct ^ keystream` 得到一段**可执行桩**，`mmap(RW)` → 写入 → `mprotect(RWX)` → `call`；
4. 桩通常是"把后面紧跟的数据逐字节 XOR 某常数写进输出缓冲区 + 设置长度"，
   读桩尾的数据按同样常数解一次就是结果。

## 6. 凭据可自造时：别解原口令，造一个等价口令

校验常是"把口令压成一个 32 位哈希再比较"。**只要比较的是哈希，任何一个原像都行**：

- FNV-1a：`h' = (h ^ c) * 0x1000193`，乘法可逆（p 为奇数），
  反推 `h_i = ((h_{i+1} * p^{-1}) mod 2^32) ^ c_i`；
- 做法：正向枚举 2~3 个字符建表，反向从目标推 2 步，取交集；
- 字符集先试可打印 ASCII（表单/命令行安全）；可打印无解时加长一位再搜
  （4 字节常有个别目标不可达，5~6 字节几乎必然有解）；
- 生成后**先用本地二进制验证返回码**，再拿去打服务端接口。

## 7. 最后一道检查：服务端是否还有"复算入口"

写报告前先把首页 HTML 读完：`<form action=...>`、`/check`、`/verify`、`/run` 这类
"把你的输入交给验证器、把 stdout 原样贴回页面"的端点非常常见。

**当容器里存在这种端点时，本地解码出来的字符串可能只是"文件不存在时的兜底"**，
真正的凭据在容器内的文件里。此时不要纠结本地结果对不对，而是：
用第 6 条造一个校验能过的等价口令 → POST 给复算端点 → 读服务端打印的真实内容。

（推论：先枚举端点、再埋头逆算法。这个顺序能省掉一次白干。）

## 8. 诱饵引擎：逻辑不产出数据 ⇒ 去 .data 找定长块

一组非常稳定的信号（三个同时出现就是它）：

1. 有一个结构完整的"引擎"：跳转表 / dispatch / 状态机 / 循环计数，看起来非常像校验器；
2. 完整 trace 一轮后发现：它只 `putc` 固定占位符、**没有任何指令写结果缓冲区**、
   没有 `mmap`/`mprotect`、没有自修改；
3. `.data` 里有一块 **N 字节高熵常量**，而**循环次数 / 打印次数恰好等于 N**。

第 3 条是作者无意泄露的长度：占位符的个数就是凭据的长度。这时：

- **不要再"补全"引擎的语义**（试图猜 handler 本该算什么），投入产出比极低；
- 把这块常量当密文，把旁边的小常量（2/4/8/12 字节表、4 字节"魔数"、opcode 常量）
  当候选密钥表，交给 `unmix` 枚举：

```
unmix(hex="<密文>", keys=["<4B 表>","<12B 块>","<program>"], prefix="<格式头>", brute=1)
```

它枚举 `rot(blob[i] OP1 key[i%L], r) OP2 c` 的整个组合空间
（`OP1` ∈ xor/add/sub/subr，`r` ∈ -7..7，`OP2` ∈ +c/-c/^c），
只保留**全部可打印**的候选，并按"像凭据"排序（成对花括号、字符集集中、命中 `prefix`）。

判定与收尾：

- 命中候选的**变换描述**（例如 `xor(k[4@0]=…) ror3 +0xef`）要能回到汇编里对上一条指令；
- 拿到的明文长度应与"占位符个数"一致 —— 不一致就说明密钥表或周期选错了；
- 报告里直接写"三/四步原子链 + 各步参数"，这比"我逆了个 VM"更可复现，也更容易被复核。

**这一步不是猜谜**：组合空间只有几万种，可打印性是强 oracle，工具毫秒级出结果。
真正花时间的永远是"判断该不该逆下去"，而不是枚举本身。
