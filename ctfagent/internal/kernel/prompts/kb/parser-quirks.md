# 解析器怪癖（绕过过滤的富矿）

过滤是"字符串匹配"，解析器是"语义"——**两者不一致的地方就是绕过点**。

## 路径归一化

```
/./x        //x        /a/../x        /x;.txt      /x%00.txt
/x%20       /x.         /X（大小写，Windows 不敏感）
```
- 有的代理/框架会先归一化再匹配黑名单 → 用 `..;/`、`//`、`%2e%2e/`
- 有的只匹配一次 → 用 `....//`（去掉 `../` 后仍剩 `../`）

## Cookie / Header 的转义

- **Sanic / aiohttp** 支持八进制转义：`Cookie: user="adm\073n"` → 值 `adm;n`
  - **必须加双引号**，不加不生效
- URL 编码在某些框架会二次解码：`%252e%252e%252f`
- 换行注入：`%0d%0a` 在部分后端能插入 header（新版本多数已拦）

## 点号 / 键名

很多语言把**点号当路径分隔符**（Spring binding、pydash、lodash、PHP 的 `parse_str`）：

```
user.name=x            # PHP 会变成 $_POST['user_name']
a.b.c                  # 对象路径，可打到原型链
__proto__[x]=1         # JS 原型污染
constructor.prototype  # 同上
```

反斜杠的语义各家不同：**pydash/lodash 里 `\.` 是"转义的点"，`\\.` 才会被当分隔符**。
当过滤条件拦 `_.`（如原型链防护）时，用转义形式既能通过检查又能被解析成路径。

## 数字 / 类型混淆

```
id=1          id[]=1        id[a]=1        id=1e0        id=0x10       id=1.0
id=true       id=null       id[0]=1
```
- 类型不匹配常导致 500（说明进去了）
- 数组传参能绕过严格比较（`in_array` / `==` / `strpos` 的经典坑）
- 哈希比较：`0e123` vs `0e456`（PHP 魔法哈希）

## 编码 / 大小写 / 空白

```
<scr<script>ipt>      %253Cscript%253E      ＳＥＬＥＣＴ（全角）
 SeLeCt                selec/**/t            sel%0aect
```
- 一次过滤后拼接会重新组合出关键字
- Unicode 归一化差异（全角/半角、NFKC）

## 判断方法

同一份输入，**发两种等价形态**（`/x` 和 `/x/`、`a.b` 和 `a\.b`），
如果响应不同，说明这条链上有解析差异 → 顺着差异继续。
