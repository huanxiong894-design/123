# 把 HTTP 响应当成 oracle

## 状态码语义

| 码 | 含义 | 下一步 |
|---|---|---|
| 200 | HTTP 层成功 | 仍需解析正文：应用可能返回验证失败、拒绝或通用 fallback；与安全基线比较 |
| 302 | 跳转 | 检查 `Location` 与会话状态；跳转本身不证明认证成功 |
| 400 | 请求/参数无效 | 阅读错误体，核对文档化的字段、类型与编码；不要直接扩大字典 |
| 401 | 需要认证或认证无效 | 只能说明本次请求未获授权；不单独证明路由存在 |
| 403 | 禁止或策略拒绝 | 记录基线与响应特征；只有题面授权且有证据时才做有限差分 |
| 404 | 未找到或被隐藏 | 与同服务的随机不存在路径比较，识别统一 fallback |
| 405 | 方法不被接受 | 查看 `Allow:`；仅在范围内按接口契约验证支持的方法 |
| **500** | 应用错误、异常或评测/校验门 | 检查正文、内容类型和稳定错误特征；状态码本身不证明注入或执行 |

**最重要的一条**：状态码只是线索。对同一路径先保留安全基线，再做有界、单变量的低风险差分。
若多个不同输入连续得到相同的通用 5xx 响应，将其视为服务故障或未通过的前置校验；停止同型变体，
记录证据并做至多一次只读健康复核。只有错误正文或受控差分明确显示输入相关行为时，才更新假设；不能仅凭 500 加码 payload。

## 差分（differential）比状态码更强

单看一个响应没用，**看"哪个输入让响应变了"**：

```
基线 = 用一个必然不存在的名字/值发一次
然后只报告：状态码变 / 长度差 > 阈值 / 响应体不再包含基线特征串
```

这能一次性从 6000 个候选里挑出真正被消费的那个参数（见 `fuzz`/`paramfuzz` 的 diff 模式）。

## 长度与哈希指纹

- 同一路径不同参数返回不同长度 → 长度就是侧信道（盲注、IDOR、文件读取都吃这个）
- 大量"200"里挑真文件：按 `长度 + 内容哈希` 聚类，与基线同簇的全丢
- 稳定、可重复的延迟差异只是候选信号；先控制请求数、负载与网络波动，并用低风险对照验证，不能单独断言盲注、SSRF 或命令执行。

## 头部也是 oracle

```
Server / X-Powered-By      → 技术栈线索；可能被隐藏或伪报，不等于精确版本
Content-Type               → 响应类型线索，仍应查看正文与接口契约
Set-Cookie                 → 会话状态/属性线索；按敏感数据处理，不当作答案或普通日志内容
Allow                      → 服务端声明支持的方法；仅在授权接口内验证
WWW-Authenticate           → 认证方案提示，不代表已获得权限
X-Forwarded-*              → 代理配置线索；不能据此断言来源地址可伪造
```

## 别只看响应体：响应头也是证据，敏感值需保护

拿到第一个响应时，检查响应头可帮助理解会话、缓存、路由与服务行为；但头部线索不自动是 flag，也不授权访问新地址。

| 位置 | 可观察线索与边界 |
|---|---|
| `Set-Cookie` | 会话状态与属性；视为凭据，不复制进报告/trace，不把它当作答案 |
| `Location` | 当前请求的跳转路径；仅跟随题面授权范围内的地址 |
| `X-*` 自定义头 | 可能有诊断、版本或 trace 信息；敏感值按凭据处理 |
| `Server` / `X-Powered-By` | 技术栈提示，不保证真实或精确版本 |
| `ETag` / `Last-Modified` | 缓存/内容变化线索；需同一资源基线对照 |
| `Content-Disposition` | 响应文件名提示，不足以证明服务器内部路径 |

快速做法：

```bash
curl -sI http://target/          # 只要头
curl -si http://target/ | head -40
```

若题目定义了 flag 前缀，可在已授权请求的工具输出中检查它；会话 cookie、Authorization 与其他凭据必须留在敏感数据处理中，不复制进报告或持久化日志。

- `Content-Encoding` 描述响应编码；不能据此推断服务端接受某种请求编码。
- 条件请求与 `ETag` 可用于比较已知资源的版本/变化；不能据此扩大到未授权资源枚举。
