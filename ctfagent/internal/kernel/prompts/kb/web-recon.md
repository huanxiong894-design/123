# Web 侦察：第一小时做什么

## 三条线并行（一轮里全发出去）

```
ports(host)        # 非标端口往往才是主线：9000/5000/6379/2375/1337...
recon(url)         # 指纹 + 目录 + 敏感文件 + 跳转 + 401/403/405 分组
http(url+"黑名单/源码路径")   # 源码、调试端点、git、备份
```

不要串行：一次 `recon` 顶十条零散 curl，`ports` 又独立于 HTTP，必须同时发。

## 目录爆破的判定

- **假 200**：先探一个随机路径（`/__noise_9f3a__`），凡与之**同状态码同长度**的命中都是噪音。
- **403 目录 ≠ 403 文件**：目录 403 通常页面更大；文件 403 只有几十字节 —— 长度差就是"文件存在"的证据。
- **401/403 = 路由存在**，只是没权限。把它记下来，拿到凭据后回来打。
- **405 = 路由存在但方法不对**：这些是 POST/PUT 接口，用 `http(method=POST, body="{}")` 拿基线错误串。
- 302 不要跟随（`recon` 已关闭跟随）：跳转目标本身就是情报（`/login?next=` 之类）。

## 源码优先级高于一切

```
/src /source /app.py /main.py /wsgi.py /application.py /server.py
/.git/HEAD /.git/config /backup.zip /www.zip /index.php.bak /config.php.bak
/debug/vars /debug/config /actuator/env /server-status /phpinfo.php
```

拿到源码后**先找四样东西**，比盲打快十倍：

1. **过滤条件**（`if 'x' not in y` / 黑名单 / 正则）→ 差异就是绕过点
2. **固定错误串**（`"URL is required"` / `"参数错误"`）→ 参数名爆破的 oracle
3. **真实参数名**（`request.json.get('...')`）→ 前端 JS 里的名字作废
4. **flag 位置/凭据/内部地址**（配置常量、环境变量、内部 URL）

## 常见误导

- 首页的"仅支持 http/https，禁止访问内网"是**注释**，不是事实 —— 一定实测。
- 前端 JS 里的接口路径和参数名**只能当候选**，以服务端行为为准。
- "服务很安全"这种题面措辞，通常意味着漏洞在**非预期位置**（旁路端口、调试端点、元数据服务）。

## 单入口 + `try_files` 回落：目录爆破全是假 200 怎么办

现象：任何非 `.php` 的路径都返回 200，正文就是首页（长度一模一样），
只有 `.php` 才会给 `404` 或极短的空响应。

- 判据：**先取两个基准**——「首页长度」和「不存在的 `.php` 的长度」；
  与首页同长的 200 一律当噪音，只有"长度不同"或"非 200"才算命中；
- 这种站点的**真实文件都是动态页**，目录爆破只爆扩展名（`*.php`），
  爆目录没有意义（目录 403 只说明 `location ~ \.php$` 之外的规则在拦）；
- 想找上传落点，就按页面里提到的路径名去试（附件目录/上传目录通常禁列但文件可直接访问）；
- 同一个站点的**指纹**（`Server`、`X-Powered-By`、错误页格式）能立刻区分
  "nginx 静态回落" 与 "应用路由 404"，决定后面是打路由还是打文件。

## 入口的"迁移提示"是最值钱的线索

- 页脚注释、`robots.txt`、旧链接里的 `TODO/migrated to ...`，往往直接写出后台入口或新地址；
- 备份/调试目录里的工具页（扫描、转发、端口探测）经常**不需要登录**，
  它们是整条链的枢纽，比后台本身更重要；
- 一旦确认入口是单点，就把"目录爆破 → 源码 → 后台 → 上传"的顺序反过来做：
  **先找能读能写能转发的点，再回头补指纹与目录**。
