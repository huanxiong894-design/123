# 自定义字节码虚拟机：怎么逆，以及怎么判断它只是个诱饵

二进制把校验逻辑塞进一台自己写的**字节码虚拟机**里，是常见加固手法。这类题有两个坑：
一是把 dispatch 逆错了，二是**整台机器其实都是诱饵**，你在里面泡两小时也拿不到东西。
下面先讲怎么把机器扒干净，再讲怎么在 15 分钟内判定"别再逆它了"。

## 1. 认出虚拟机（三个特征同时出现）

- 主循环长这样：`movzx eax, BYTE PTR [prog_base + pc]` → 变换成下标 → 查表 → `jmp`；
- 有一张 **int32 跳转表**：`movsxd rax, DWORD PTR [table + idx*4]` 紧跟 `add rax, table`、`jmp rax`；
- 程序本身是一段 .data 字节，长度由 `cmp pc, <常数>` 硬编码在循环条件里。

## 2. 把"机器"扒成伪代码（这一步必须做完）

1. **跳转表基址**：`add rax, rX` 里的 rX 就是表基址，表项是**相对基址的有符号偏移**，
   不是绝对地址 —— 直接当绝对地址用会全盘错位。
2. **opcode → 下标的反函数**：常见形式是 `idx = (op + K) & 0xff`，于是 `op = (idx - K) & 0xff`。
   把表内下标翻回 opcode，得到"合法 opcode 集合"；落在表外的 opcode 一律是 no-op。
3. **程序长度与状态寄存器**：循环条件给出程序长度；找**每次自增**的那个寄存器（常叫 `r14`/`r15`），
   它就是数据索引/输出计数；handler 里被 `lea` 反复恢复的常量指针就是输入表基址。
4. **逐字节翻译**：把程序字节按映射表翻成指令序列，写成几十行伪代码。
   这一步做完，后面的判断才有依据。

## 3. 三类 handler，先给每条指令分类

| 形态 | 含义 |
| --- | --- |
| 写内存/写输出缓冲区 | 真逻辑，重点看 |
| `movzx eax, BYTE PTR [表+索引]` 之后立刻 `jmp` 回循环头 | **dead load：读了不用**，decoy 的典型笔误 |
| `putc(常数)` / `puts(固定串)` | 只打印固定字符，**不携带任何数据** |

只有第二、三类，且没有任何写结果缓冲区、没有 `mmap`/`mprotect`、没有自修改 ⇒ 整台机器是诱饵。

## 4. 判定"这机器是诱饵"的三条硬证据

1. 完整跑完一轮，输出全是同一个固定字符（`.`、`*`、`#`），**一个字节的 .data 内容都没被打印**；
2. 执行轨迹里没有指令写结果缓冲区/输出数组；
3. **.data 里存在一块 N 字节高熵常量，而循环次数/打印次数恰好等于 N**。

第 3 条是题眼：作者无意中把"结果长度"告诉了你。这时不要再补全虚拟机语义，
直接按"数据在 .data、机器是填充物"往下走。

## 5. 真凭据的还原：不要把算法当谜语猜，要当组合空间枚举

那块定长高熵常量通常被一层**按字节的原子链**混淆过，参数散落在旁边的小常量里
（2/4/8/12 字节的查找表、立即数、opcode 常量）。结构几乎总是这一族：

```
plain[i] = C( rot( blob[i] OP1 key[i % L] , r ) )
```

- `OP1` ∈ `xor / add / sub / subr`（`subr` = `key - blob`）；
- `r` ∈ `-7..7`（0 表示不旋转）；`C` ∈ `+c`、`-c` 或 `^c`；
- `key` 来自题目里的小常量，**连它的任意长度窗口都要试**（表长 12 不代表周期 12）。

**可打印性就是 oracle。** 31/40/48 字节全部落在 `0x20..0x7e` 是极强的约束，
错误参数组合几乎不可能满足。工具 `unmix` 就是干这件事的：

```
unmix(hex=..., keys=["表1hex","表2hex",...], prefix="<已知格式头>", brute=1)
```

- `keys` 给足：把 .data/.rodata 里所有长度 ≤16 的常量、以及它们的连续窗口都丢进去；
- `prefix` 给平台/程序自己声称的格式头，命中会直接顶到第一；
- 返回每条候选的**变换描述**（`xor(k[4@0]=... ) ror3 +0xef` 这种）+ 明文 + hex，
  拿描述回到汇编里能对上一条指令，才算验证过。

## 6. 机器是真的、但"少了写回"

如果轨迹显示有 load、有自增、有循环，但结果缓冲区永远是旧的 —— 那多半是作者笔误，
**同时也是题眼**：handler 里的读地址已经告诉你"每轮读哪些字节"（`blob[i]`、`table[i % k]`）。
缺的只是一个二元运算。把 `(blob[i], table[i % k])` 的所有二元组合各试一遍
（`xor / add / sub / subr / ror / rol`，旋转量可以取 `i & 7`、`i % 8`），
**只要有一组全 printable 就是它**。

## 7. 常见坑

- 跳转表项是**相对基址**的偏移，别当绝对地址；
- opcode 下标常被 `& 0xff` 折叠，"非法 opcode"不一定是数据，可能只是 no-op；
- 条件跳转的目标常是 `operand ^ 常数`（可逆混淆），那个常数往往就是循环里反复出现的字节；
- 库函数（`putc`/`printf`）会破坏 caller-saved 寄存器，handler 里"恢复常量指针"的那条
  `lea` / `mov rcx, imm` 才是它的真实基址 —— 别自己猜；
- 循环计数（`0x186a0` 这种）只是防止死循环的保险丝，不是参数字节数，别拿它当长度。
