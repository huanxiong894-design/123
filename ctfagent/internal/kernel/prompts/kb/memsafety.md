# 线协议的内存安全：四类必查缺陷

目标是一个**自己写的小服务**（TCP 行协议、`HELP` 列命令、几百字节的 C 程序），
题面说"内存安全缺陷"时，不要一头撞进 ROP —— 这类服务里**能直接读出凭证的缺陷**
比想象中多。按下面四类依次试，通常前两类就能拿到东西。

## 0. 先摸清协议面（别急着打）

```
连上 → 收 banner → 发 HELP
→ 把 HELP 里每个动词都正常用一遍，记下每条命令的**输出形状**
→ 再对每个动词做边界扫描：空参、超长参、负数、超大数、重复、缺参
```

边界扫描的最小集合：`0 / 1 / 上限-1 / 上限 / 上限+1 / -1 / 超大值`。
**同一个动词在不同边界返回不同错误码**（例如 `250 ok` / `404 no entry` / `550 failed`），
这个差异就是后面所有 oracle 的基础。

> 关键约束：这类服务的输入最终都进 C 字符串，**payload 里不能有 `0x00`**。
> 所以"写一个完整 8 字节地址"通常做不到；能做的多是**部分覆盖**（只改低 1~2 字节，
> 高位保持原值）或**改某个整数型 guard/长度变量**。

## 1. 声称长度 > 实际长度 = 越界读（最值钱）

服务让你"先设内容，再按长度取回"时，**回声长度是否等于真实内容长度**必须验证：

```
SETPAYLOAD A          # 实际 1 字节
FETCH/HEARTBEAT 4096  # 索要 4096 字节
```

若返回 4096 字节（前 1 字节是自己写的，后面是内存），就是 length-trust 缺陷。
把长度阶梯式放大（`64 / 256 / 4096 / 16384 / 65536`），**在返回的原始字节里搜凭证**——
凭证常常就躺在同一进程的全局/栈缓冲区里，一次越界读直接带走。

要点：
- 逐级放大，太大会把连接撑爆或触发截断（`65536` 级常常只回一小段）；
- 拿到的是**二进制**，别 decode 成文本再搜，直接在 bytes 上用正则搜；
- 顺带记下泄漏里的指针（`0x55…`/`0x7f…`/`0x7ffd…`），后面打溢出时能当基址。

## 2. "dump / build / export" 会把未初始化结构原样吐出来

凡是有 `DUMP`、`BUILD`、`EXPORT`、`SHOW`、`STATE` 这类"把内部结构打出来"的命令，
**先用最小输入触发一次**：只设 1 个字段就 dump，然后逐字节看输出里 NUL 之后的内容。

典型形态：结构体里有一张固定大小的表（头表、槽位表、历史环形缓冲），
字段只填了一部分，导出时却按**整表长度**打印 —— 未初始化区里就可能是凭证或指针。

识别特征：输出里出现**成片的 `\x00` 后突然跟着可读字符串**，或者 `[LAST]`/`[HIST]`
这类"最后一条/历史"的行比自己的输入长。看到就先把整段原始字节存下来再分析。

## 3. 有符号偏移 / 索引：负数是绕过长度校验的捷径

写入类命令（`COPY <off> <data>`、`PATCH <idx>`、`SET <slot>`）经常只检查
"上界不越界"，忘了下界：

```
COPY 1023 AAAA     # 550 failed（上界挡住了）
COPY -4   AAAA     # 250 wrote 4 bytes at offset -4   ← 下界没查
```

**缓冲区前面通常就放着校验变量/守卫值/长度字段**（这类自测服务甚至会提供一个
"满足条件就吐凭证"的入口，比如 `REVEAL`/`UNLOCK`）。所以先用一次小写入探 -1/-4/-8，
再用 `DUMP` 看守护值有没有被改。

顺带：索引是 `int` 而比较用无符号、或 `atoi` 后没查符号，都会产生同样的洞。

## 4. 定长缓冲区拼接：溢出阈值先测出来，溢出前先要泄漏

`LIST`/`SHOW ALL`/`BUILD RESPONSE` 这类命令会把多条记录拼进一个**定长栈缓冲区**
（常见 1~4 KB），拼接时不校验总长。

做法：

1. **测阈值**：用等长记录（例如每条 63 字节）逐条增加，找"能正常返回"和"连接被断开"
   的分界点，这个点就是缓冲区大小的量级；
2. **测泄漏**：在**刚好不崩**的条数上，观察最后一条记录后面是否跟着多余字节。
   缓冲区没有被正确 NUL 结尾时，打印会把相邻栈内容一起吐出来 —— 常见泄漏出
   **栈指针**（`0x7ffd…`）、**代码指针**（`0x55…`）和小整数（循环变量/长度）；
3. **再谈覆盖**：拿到栈地址/代码地址后，才考虑用后续记录做溢出改返回地址。
   注意第 0 节说的 NUL 约束 —— 多数情况只能做**低字节部分覆盖**，
   所以优先想"让程序走另一条分支"，而不是"拼完整 ROP 链"。

判定"这条路走通"的标志：溢出后程序**打印出凭证**或**行为可控地切换**，
而不是单纯崩溃。只崩溃一次不算找到利用点，先回去补泄漏。

## 5. 定长槽位不补 NUL：列表命令顺着槽边界读到隔壁

最容易被忽略的一类：记录型服务（`STORE`/`PUT` 一条条存）给每条记录分**定长槽位**
（64 / 128 / 256 字节）。写入路径只在"内容比槽位短"时补 NUL 结尾，
而"打印某条记录"用的是 `%s` / `strlen`。

于是：**写入一条 ≥ 槽位长度、且不带 `0x00` 的内容，打印这条记录就会一路读到下一个对象**。
下一个对象常常是 gid 表、会话表、或者干脆就是凭据缓冲区 —— 一次 `LIST` 直接带走。

做法（顺序很重要，别跳步）：

1. **测槽位大小**：用等长可打印 payload 递增（`16 / 32 / 40 / 63 / 64 / 65 / 128 / 256`），
   看哪一档开始"能存但语义变化"（回显被截断、`CHECK` 失效、越界后能读到别的东西）；
2. **填满不封口**：用**全可打印**字符填满槽位（`Z`×N 最好，边界一眼可见），
   绝对不要在 payload 里带 `0x00` —— 那等于自己补了 NUL；
3. **找打印路径**：`LIST` / `SHOW` / `GET LAST` / `HIST`，特别关注**最后一条**记录
   （很多实现只给最后一条做特殊格式化，例如 `[LAST] <内容>`）；
4. **判定**：输出里出现 `Z`×N 之后**紧跟**一段你没写入的可读串 ⇒ 越界读成立。
   把返回的**原始 bytes** 存下来再分析，不要先 decode；
5. **变体**：多字节写（长度来自输入的 `memcpy`）覆盖相邻槽的"长度/used 标志"，
   把下一个槽标成"已用"，再用 `LIST` 读它 → 未初始化内存原样吐出（回到第 2 类缺陷）。

这个缺陷和"缓冲区溢出"是两个方向：**溢出要崩，越界读只要输出变长**。
先用"输出是否比输入长"这一条判据筛一遍，比去找崩溃点便宜得多。

## 一句话清单

```
长度回显 → 放大取回 → bytes 里搜凭证
dump/build → 最小输入 → 看 NUL 之后
偏移/索引 → 先试负数 → 看 guard 是否变
多条记录拼接 → 找崩溃阈值 → 阈值下方找泄漏 → 再谈覆盖
定长槽位不补 NUL → 填满可打印字符 → LIST 的"最后一条"比输入长 = 越界读
```
